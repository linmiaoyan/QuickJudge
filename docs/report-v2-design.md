# 学生报告 v2：范例对照与结构梳理

> 参照材料：`2023级1班/2班_嘉兴应用文.pdf`、`2023级1班/2班_嘉兴市2025年12月高三教学测试.pdf`（每生 2 页，Chrome 打印输出）
> 对照对象：当前 `/portal` 学生端 `essayHtml()` 的实际渲染
> 结论一句话：**范例的「版式」已经对了，但「教学含量」不到位**——语言错误没落进语篇、改写只给整句不给角度、衔接块名存实亡、范文和语料是全批通用而非个人专属。

## 一、范例文本的结构（逐块拆解）

范例每生 2 页，固定 8 个区块：

| # | 区块 | 内容形态 | 位置 |
|---|---|---|---|
| 1 | 卷头 | 学校 / 班级 / 姓名 / 学号 / 作答时间，页脚「第 X 页 / 共 2 页」 | 页首 |
| 2 | 题型 + 得分 + 评语 | `应用文写作`；`得分：7（满分15，最高分12，班级平均分8.2）`；一段中文评语 | 页首 |
| 3 | **批改结果** | `（要求60词，共写150词）` + **原文全文，行内划改**：错误处划掉、紧跟正确写法、旁边贴中文类型标签（介词错误 / 拼写错误 / 大小写错误 / 固定搭配错误 / 用词错误 / 单复数错误 / 所属关系错误 / 句子成分残缺 / 表达冗余 / 冠词错误 / 语态错误 / 表达混乱 / 动词不定式错误） | 第 1 页主体 |
| 4 | 更多表达 | 3 组「我的原文 / 更多表达」（整句改写） | 第 1 页下部 |
| 5 | 逻辑衔接提升 | 每条形如「逻辑衔接词」标签 + 我的原文 / 逻辑提升 / 修改原因 | 第 1 页下部 |
| 6 | 学生佳句（高级句式） | 按手法分组：强调句式 / 倒装句 / 复杂结构，句末署名（周芊妤） | 第 1 页尾 |
| 7 | 学生佳句（高级词汇） | 按类型分组：高级短语 / 高级词汇，句末署名 | 第 2 页首 |
| 8 | 个性化范文 + 题目专属语料 | 页 2：`个性化范文`（贴着学生写）+ `范文`（通用）；语料按**要点**分组，每条 `【语料N】+【翻译N】` | 第 2 页 |

**范例的 3 个硬伤**（正好对应你要补的部分）：

1. **错因缺失**。行内只有类型标签（"拼写错误"），没有一句"为什么错"。学生知道被划了，但不知道错在规则上。
2. **「更多表达」不分角度**。3 句改写混着词汇替换、句型调整、语法修补，学生没法归类记忆，也看不出"我这次到底缺词汇还是缺句式"。
3. **「逻辑衔接提升」名不副实**。两条内容实际都是语法修补（补主语 `it will`、把 `article` 改 `a`），全程没出现一个衔接词，更没有"前后是什么逻辑关系"。

## 二、范例 vs 现有系统：差在哪

| 维度 | 范例 PDF | 现有系统（`/portal`） | 判定 |
|---|---|---|---|
| 语言错误 | 内联在原文里划改 | `errors[]` 独立列表：`quote → fix + why`，脱离语篇 | **要改**：原句在哪一行都看不出来 |
| 错误类型 | 13 类中文教学术语 | 11 类英文枚举（grammar / spelling / …）+ `ERR_TYPE_CN` 中文映射 | 可复用，但需扩到"固定搭配/所属关系/成分残缺/表达冗余"等 |
| 错因 | 无 | 有 `why`，但埋在列表里 | **要合并**：内联标注 + 错因速查 |
| 更多表达 | 3 句整句改写 | `rewrites[]`：original / improved / focus | **要拆**：拆成「高级词汇」「高级句式」两个角度 |
| 逻辑衔接 | 有区块、无实质 | 完全没有 | **新增** |
| 佳句 | 分「高级句式」「高级词汇」+ 手法归类 + 署名 | 只有本篇 `sentence_award` 一句 + 全批 `awards[]`（有 why/takeaway，未分类） | **要分类** |
| 范文 | 个性化范文 + 通用范文 | **没有** | **新增** |
| 语料 | 按要点分组，每条带翻译 | 全班一份 `phrases / sentences / patterns / pitfalls`，**无翻译**，且前端把 dict 直接 `esc()` 出来，页面显示成 `{'sentence': '...', 'meaning': '...'}` | **要重构**（含一个现成 bug） |
| 得分语境 | 满分 / 最高分 / 班均 | 有 score / level；批次有均分，但不进学生报告 | 顺手补 |
| 词数 | 要求 vs 实写 | 无 | 顺手补 |

> 顺带两个现存问题：`portal.html` 的 `batchHtml()` 里 `co.sentences.map(s => esc(s))` 假设 sentences 是字符串，实际是对象 → 已确认会打印 Python dict 原文；`co.phrases` 的"英文（中文释义）"只是提示词里的软要求，没有校验，出现漏译就整条失去意义。

## 三、新版报告：六段结构

按「由小到大」排：先看语篇 → 再看词 → 再看句 → 再看衔接 → 最后给成品和弹药。每段一个动作，学生读完知道下一步练什么。

```
┌ 0 卷头     得分 / 满分 / 班均 / 最高 / 词数（要求 vs 实写）
├ 1 语篇批改  原文全文，行内划改 + 编号；下方「错因速查」按编号列类型和一句话原因
├ 2 高级词汇  【表】原表达 → 升级表达 → 整句效果 → 一句话为什么更好    3-5 条
├ 3 高级句式  原句 → 升级句；标签：手法；附「扩了什么内容」           2-3 条
├ 4 逻辑衔接  原句 → 升级句；标签：before→after 衔接词；关系类型      2-3 条
├ 5 个性化范文 贴着这个学生写的 100-120 词全文 + 改写说明（保留了什么）
└ 6 专属语料  按本题目要点分组，每条【语料】+【翻译】+【用在哪】      每要点 2-3 条
```

> 读后续写换两块：4 变「内容提升」（按情节节点），6 的语料按「承接 / 转折 / 升华」分组，详见第七节。

### 1. 语篇批改（替代现在的「语言错误」列表）

- **只在原文上标，不再单列一份脱离上下文的清单**。
- 呈现：`~~writting~~ writing` + 右上角编号 `②`；句末不打断阅读；正文字号不变。
- 编号在文末汇总成「错因速查」：`② 拼写 · write 加 -ing 要先去掉不发音的 e，也不能双写 t`。
- 为什么不把类型直接贴在行内（范例的做法）：一行里挤 4 个标签会把 150 词的短文读成天书；编号 + 速查表既保留"当场可见"，又给得起完整错因。
- 上限：**按实际错，不设下限**（不许凑数）；超过 12 处时，只标影响理解的，其余在速查表里合并成"同类还有 N 处"。
- 硬约束：`quote` 必须在 `text` 中**原样且唯一**出现（前端靠它定位）；同一片段只标一次（拼写与语法重合时取最具体的一类）。

### 2. 高级词汇（新）

一条 = 三行：

| 原表达 | 升级表达 | 整句效果 |
|---|---|---|
| `enhance a vast stress` | `impose considerable pressure on` | `School life can impose considerable pressure on students.` |

再加一句话说明为什么（搭配更地道 / 语义更准 / 语域更正式）。**必须给整句**——单词换掉不改搭配，十次有八次换出病句。挑的是"没错但平"的表达，不是错句（错句归第 1 段）。

### 3. 高级句式（新）

一条 = `原句 → 升级句`，加两个必填标签：

- **手法**：非谓语作状语 / 定语从句 / 名词性从句 / 强调句 / 倒装 / 独立主格 / 平行结构 / 分词后置定语 …
- **扩了什么**：把"重要"具体成"让音乐抵达听众"这种——句式升级必须**同时扩内容**，否则只是换个壳子的同义改写，学生学不到东西。

上限 2-3 条。一句只讲一个手法，不叠加。

### 4. 逻辑衔接（新）

这是范例最空的一块，也是最容易做出差异的一块。三条路径，按需给：

1. **补**：两句之间本来有逻辑，学生没写连接词 → 补一个，并说明是什么关系。
2. **换**：`First and foremost / Besides / Last but not least` 这类模板三连 → 换成关系更准的（`To begin with` / `Equally important` / `Above all`）。
3. **改关系**：学生用错了关系词（上文在讲支持理由，下文突然 `Thus` 提建议——不是因果，是目的过渡）→ 换词并点破。

每条必须写清 `关系类型`（并列 / 递进 / 转折 / 因果 / 举例 / 对比 / 总结 / 目的）和 `before → after` 两个衔接词（before 可以是"无"）。

### 5. 个性化范文（新）

**关键差异：不是全批一份范文，是"这一篇的升级版"。**

- 保留学生自己的要点顺序、观点、素材（他写昆明就还是昆明，不许换成"长城"）；
- 只升语言：把第 2/3/4 段给的升级项真的用进去；
- 词数贴题目要求（±10%），不分段乱加；
- 附一句「改写说明」：保留了什么、动了几处、还差什么（诚实告诉学生这版仍不是满分卷）。
- 通用范文可以另存一份做对照，但**不要**顶替个性化范文——学生会背通用范文，个性化范文才会让他觉得"这是我写的"。

### 6. 题目专属语料（重构）

现在的语料是 `phrases / sentences / patterns / pitfalls` 四堆，按语言形式分类，学生不知道哪条用在哪。改成**按要点分组**：

```
要点 1 表达对「每日金曲」栏目的看法
  【语料】A well-chosen song can lift the spirits of an entire campus.
  【翻译】一首选得恰当的歌，能振奋整个校园的精神。
  【用在哪】开头段表态之后，用来补一句理由。
要点 2 对栏目内容或形式提出建议
  ...
```

- 每条**必须有中文翻译**（这是背诵的前提，也是现在的缺口）；
- 每条加 `用在哪`（十个字以内：开头表态 / 主体第一层 / 结尾请求回应）；
- 保留原 `pitfalls`，但并到对应要点下，不再单列。

## 五、提示词要写死的几条规矩

1. **内联可定位**：`errors[].quote` 必须是 `text` 的原样子串、长度 ≤ 8 词、全文唯一；同一处不重复报。
2. **不许凑数**：没有就返回空数组。宁可 3 条真错，不要 8 条"改了等于没改"。
3. **升级项只从原文挑**：词汇/句式/衔接都必须 `original` 出自学生原文，禁止凭空造一句学生没写过的话再"升级"。
4. **词汇必须给整句**；**句式必须写 `added`**（扩了什么内容）；**衔接必须写 `relation`**。
5. **范文不许加素材**：地名、活动名、人物一律沿用学生原文；学生写错的事实（如把杭州写成北京）在范文里改对，但要在 `note` 里点出来。
6. **数量配额**：词汇 3-5、句式 2-3、衔接 2-3、语料每要点 2-3。超过就是噪音。

## 六、前端内联标注算法（可直接抄）

```js
// 依赖：errors[].quote 能在 text 中定位
function annotate(text, errors) {
  const marks = [];
  errors.forEach((e, i) => {
    const q = (e.quote || '').trim();
    if (!q) return;
    const at = text.indexOf(q);          // 只取首次出现，避免重复标
    if (at < 0) return;                  // 定位失败 → 降级进错因表，不上内联
    marks.push({ at, end: at + q.length, i, e });
  });
  marks.sort((a, b) => a.at - b.at);
  let out = '', cur = 0;
  for (const m of marks) {
    if (m.at < cur) continue;            // 区间重叠 → 跳过被包含的短条目
    out += esc(text.slice(cur, m.at));
    out += `<del class="err">${esc(text.slice(m.at, m.end))}</del>`
         + `<ins class="fix">${esc(m.e.fix || '')}</ins>`
         + `<sup class="mk">${m.i + 1}</sup>`;
    cur = m.end;
  }
  return out + esc(text.slice(cur));
}
```

配套 CSS：`del.err` 红色删除线；`ins.fix` 绿色、无下划线、字号同正文；`sup.mk` 小号圆圈数字。定位失败的条目仍然进「错因速查」，标 `（原文位置未能匹配）`，不要静默丢掉。

## 七、题型分叉：应用文 / 读后续写

四份范例里有两套模板，不能套一个结构：

| 区块 | 应用文（嘉兴应用文） | 读后续写（高三教学测试） |
|---|---|---|
| 3 语篇批改 | 全文一段连续批注 | **按段落批注**；某段没写就明确写「该段您暂未作答」 |
| 4 | 高级词汇 | 高级词汇（同） |
| 5 | 高级句式 | 高级句式（同） |
| 6 | **逻辑衔接提升**（衔接词） | **内容提升**（情节推进、细节、情感层次） |
| 7 | 个性化范文 | 范文（范例里没做个性化） |
| 8 | 语料按**要点**分组 | 语料按**情节节点**（开头承接 / 中段转折 / 结尾升华）分组 |

新增「读后续写」的 `content_upgrade`，字段与应用文的 `cohesion` 同构，只是把 `relation` 换成 `节点`：

```jsonc
{"original": "…", "improved": "…", "node": "第一段承接", "added": "补了一个动作细节", "why": "…"}
```

**空区块的写法照抄范例**：宁可写「因内容太短，无法生成」，也不要留一个空标题。范例里「该段您暂未作答噢~」「因'内容太短'的原因，无法生成相关内容」这两句，比一整块空白有用得多。

### 错误类型词表（从四份范例归纳，共 23 类）

应用文常见 13：拼写 / 大小写 / 冠词 / 介词 / 单复数 / 所有格（所属关系）/ 固定搭配 / 用词 / 语态 / 动词不定式 / 句子成分残缺 / 表达冗余 / 表达混乱
读后续写另加 10：时态 / 分词 / 动名词 / 连词 / 代词 / 词性误用 / 并列结构 / 从句 / 标点 / 逗号连接两个完整句子（comma splice）

这比现在的 `grammar / tense / agreement / article / …` 英文枚举更贴教学习惯，也直接决定行内标签的可读性。建议 `type` 直接存中文，前端不再映射。

## 八、落地顺序（建议）

| 步 | 动作 | 影响 |
|---|---|---|
| 1 | 修 `batchHtml()` 的 sentences 渲染 bug（先判字符串/对象） | 页面立刻不再出 `{'sentence': …}` |
| 2 | 改 `ESSAY_PROMPT_TEMPLATE`：`errors` 加中文类型 + `why` 收紧；新增 `vocab_upgrades` / `pattern_upgrades` / `cohesion` / `model_essay` / `word_count`；删掉 `rewrites`（被 2、3 段吸收） | 一次调用多产出，耗时增加约 15-25% |
| 3 | `_norm_essay_result` 做归一化 + 校验：quote 定位、去重、排序、条数上限 | 老数据无新字段时自动隐藏对应区块 |
| 4 | `portal.html` 重排 `essayHtml()`：语篇 → 词汇 → 句式 → 衔接 → 范文 → 语料 | 主要工作量在前端 |
| 5 | 改 `CORPUS_PROMPT` 为 `points[]` + `trans`，`batchHtml()` 跟改 | 语料从"四堆"变"按要点" |
| 6 | `student_report_generator.py` 接新字段出打印版（A4 两页，对齐范例版式） | 老师要发纸质版时需要 |

回归点：老批次没有新字段时必须优雅降级（区块整个不渲染，不能出现空标题）；`_norm_essay_result` 的 quote 定位率建议打日志，低于 80% 说明模型在改写原文而不是引用。

产出 3 条词汇升级、2 条句式、2 条衔接、一篇个性化范文。页面预览见 `docs/preview-report-v2.html`。

与上面设计稿相比，落地时改了 5 处：

1. **`rewrites` 没有真删**。归一化里仍保留，只为老记录降级用（新记录不再产出）。前端优先 `pattern_upgrades`，
   没有才回退到 `rewrites`。
2. **编号只给真正画上去的条目**。两条错误位置重叠时（如「one of the most must-see views you have ever see」
   与其中的「you have ever see」），短的画不上去；这类条目排在错因表末尾、标「位置重叠」，不占编号——
   否则学生会对着 ① 找不到 ②。
3. **范文加了二次压缩**。提示词写了「词数必须落在 0.9–1.1 倍」，实测 8B 仍写到 236 词（要求 80）。
   现在超 1.35 倍时用文本模型重写一次（保留全部地点、只删铺陈），实测能压到 80 词。
   压缩结果和说明都会告诉学生「已按题目要求压到 80 词」——不藏。
4. **语料缓存做了版本号**。老缓存没有翻译、也没按要点分组，命中它等于让学生看旧版；
   现在只认 `version: 2`，老话题会重新生成一次。
5. **批阅调用加了 20015 重试**。实测遇到过一次 SiliconFlow 返回「JSON decode error」（大请求体抖动），
   重试一次即过。

### 代价（必须知道）

- **单篇耗时 45s → 约 200s**。输出是原来的 3 倍，40 篇串行超过 2 小时。想让 v2 进课堂，下一步要做的是
  **批阅并发**（现在是串行），不是换更贵的模型。
- 8B 的衔接判断偏弱：会把「Moreover → Furthermore」这种同义替换当成升级。提示词已要求只报
  「该有却没有 / 关系用错」，但仍有漏网——这一块需要老师抽查。
